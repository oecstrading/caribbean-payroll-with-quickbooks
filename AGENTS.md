# Application rules
- Account-free employees use employee_records with a durable employment key, never fabricated auth users; payroll reads both directories atomically and saves account-free payslips separately to preserve auth-bound foreign keys.
- Employee HR files use private storage and employee_documents metadata; HR manages files, staff read only explicitly shared own files, and downloads use short-lived signed URLs to keep confidential records private.
- Department payroll approval is an atomic authenticated RPC over live profiles; retain employee-name and department snapshots on payslips, reject duplicate employee/month approval, and consolidate saved runs by period without current-profile joins.
- Simulation clocks and punches use dedicated tables and authenticated RPCs; never override device time or feed simulated records into live attendance, payroll, billing or compliance. Resets start a new retained run rather than deleting history.
- Treat src/lib/sample-data.ts records as fictional demonstrations, never as authentication users; this prevents invalid payslip links and accidental live payroll.
- Serve the versioned user manual from public/training and author it with scripts/generate-user-manual.py so public downloads do not depend on database availability.
- The same manual generator also authors the versioned brochure; both Training Hubs use src/lib/training-resources.ts for current static PDFs so user-uploaded documents remain untouched.
- AI Payroll Officer is an on-demand, role-validated, read-only Edge Function using the Gateway SDK; send anonymized draft amounts/flags only, invalidate review on preview changes, and retain the atomic manager approval RPC as the sole payroll-save boundary.
- User creation and deletion authorization must be enforced server-side independently of operational access; hidden navigation is not a security boundary.
- Employee folders use live profiles with validated HR details, manager-edit/admin-create-and-delete controls, and reversible soft deletion; this preserves payroll history without deleting authentication accounts.
- Employee sample edits remain session-only and explicitly separate from live profiles so fictional identities never enter payroll or account APIs.
- Platform selects retain native form semantics and string values with global styling and the shared native-select wrapper for HR/payroll controls; Input exposes native date/time pickers, while open-ended HR fields use ValuePicker with source-isolated directory suggestions to preserve custom details and sample/live boundaries.- Payroll runs carry pay type and start/end dates; salary and statutory thresholds are prorated by a period factor computed identically in src/lib/pay-period.ts and the payroll_period_factor SQL function, and approval rejects overlapping paid periods per employee to prevent double pay.
