# Application rules
- Company super-administrator delegation uses a separate protected authority table; platform delegation stays independent. Server-side transactions protect self/last-super-admin removal, tenant scope and retained financial records.
- Company enabled modules cap every role, including company admins, through shared route checks and has_workspace_access; platform company administration stays independent. Setup/edit checkboxes persist the cap, and production workspaces suppress demo data and simulated accounting posts.
- Workforce clocks enforce configured identity/methods, server-time punches, bcrypt PINs and assigned-site geofencing; enabled staff get own-clock access without management rights. Missing-punch suggestions require confirmation; opt-in attendance payroll revalidates rates/hours atomically and snapshots its basis. Reuse the company-isolated alert scheduler; never mix simulated timesheets into live pay.
- Platform authority is separate from company roles. Setup uses authenticated functions and service-only atomic RPCs with verified email, hashed expiring single-use invitations, locks and no reassignment. Platform edits expose metadata only. Versioned industry packs persist reviewed metadata and initialize missing new-company clocks, never existing payroll/taxes/schedules; AI suggestions require platform authority or verified invitations.
- Live security tests use an RLS-bound requesting-user session and fixed account-free fixtures, never privileged credentials; run setup/cleanup through approved data tools and keep live writes opt-in outside normal CI tests.
- Organization membership is server-controlled; tenant RLS, relational validation and privileged functions must agree. Failed access verification denies entry with a retryable error, never a missing-membership claim; unassigned identities cannot access company records.
- Clear client query caches when the signed-in identity changes so one company's data never shows in another workspace.
- Operational photos/audio and applicant files use private storage and short-lived signed reads, resolving legacy public references to preserved object paths; branding and explicitly public training resources remain public by design.
- Employee loans are separate from fixed deductions: bounded period repayments and balance updates occur only inside the atomic payroll approval RPC and must be withheld from net pay.
- Samples and flat test taxes never enter live payroll. The public client demo uses local fictional identities/roles only, with no service calls; AI, approval, QuickBooks and email outcomes are explicitly simulated to protect production records.
- Workspace module defaults and route eligibility live in workspace-access; server-stored per-user module overrides may narrow role access, never elevate employees. Navigation, dashboard cards and page guards share one access check, enforced independently by database policies and RPC guards. Refresh roles from live tables, not stale JWT claims; administrators keep full access.
- Account-free employees use employee_records with a durable employment key, never fabricated auth users; payroll reads both directories atomically and saves account-free payslips separately to preserve auth-bound foreign keys.
- Employee HR files use private storage and employee_documents metadata; HR manages files, staff read only explicitly shared own files, and downloads use short-lived signed URLs.
- Department payroll approval is an atomic authenticated RPC over live profiles; retain employee-name and department snapshots on payslips, reject duplicate employee/month approval, and consolidate saved runs by period without current-profile joins.
- Simulation clocks and punches use dedicated tables and authenticated RPCs; never override device time or feed simulated records into live attendance, payroll, billing or compliance. Resets start a new retained run rather than deleting history.
- AI Payroll Officer is an on-demand, role-validated, read-only Edge Function using the Gateway SDK; send anonymized draft amounts/flags only, invalidate review on preview changes, and retain the atomic manager approval RPC as the sole payroll-save boundary.
- Employee-folder login setup reuses server-authorized account services. Employment keys remain stable when linking logins; PIN users have unique usernames, and allowlisted self-service never changes pay or roles.
- Employee folders support reversible archiving and separately confirmed administrator-only permanent removal through a JWT-validated Edge Function and service-only tenant-checked RPCs; migrate auth-linked payslips to a non-restorable minimal financial identity before deleting login accounts, and retain resumable cleanup jobs so storage/auth failures cannot erase financial history.
- Platform selects retain native form semantics and string values with global styling and the shared native-select wrapper for HR/payroll controls; Input exposes native date/time pickers, while open-ended HR fields use ValuePicker with source-isolated directory suggestions to preserve custom details and sample/live boundaries.
- Payroll runs carry pay type and start/end dates; salary and statutory thresholds are prorated by a period factor computed identically in src/lib/pay-period.ts and the payroll_period_factor SQL function, and approval rejects overlapping paid periods per employee to prevent double pay.
- AI Paymaster is a daily-scheduled plus on-demand Edge Function that writes per-company payroll drafts, flags and reminders with a per-company lease and 6h throttle; it never approves or pays, and the browser can only acknowledge drafts, keeping manager approval on the Payroll page as the sole save boundary.
- Spreadsheet (salary-sheet.ts, onboarding-sheet.ts) and pay-slip PDF (payslip-pdf.ts) imports parse client-side, ask questions, compare to platform rules and write only after admin approval; slip saves use approve_payslip_import with payroll-approval guards. The template covers every stored field; extra options live in hr_details.
- Read nested AGENTS.md. Versioned visual guides use the shared Training list; document verified behavior only.
