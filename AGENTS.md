# Application rules
- Company super-administrator delegation uses a separate protected authority table; platform delegation stays independent. Server-side transactions protect self/last-super-admin removal, tenant scope and retained financial records.
- Company enabled modules cap every role, including company admins, through shared route checks and has_workspace_access; platform company administration stays independent. Setup/edit checkboxes persist the cap, and production workspaces suppress demo data and simulated accounting posts.
- Workforce clocks use server-time punches in separate workforce tables, company/employee code plus bcrypt PIN or authenticated identity, and server-checked assigned-site geofencing. Missing-punch suggestions need recorded manager confirmation; opt-in hourly/daily attendance payroll revalidates rates/hours atomically and snapshots its basis. Reuse the existing attendance scheduler for company-isolated alerts, never mix simulation or sample timesheets into live pay.
- Platform company administration uses a separate protected authority table, never company-admin roles; invitation redemption runs through an authenticated Edge Function and service-only atomic RPC with verified email, hashed expiring one-use tokens, row locks and no existing-company reassignment. Platform company editing exposes metadata only, never customer payroll or HR data.
- Live security tests use an RLS-bound requesting-user session and fixed account-free fixtures, never privileged credentials; run setup/cleanup through approved data tools and keep live writes opt-in outside normal CI tests.
- Organization membership is server-controlled; tenant RLS, relational validation and company-scoped privileged functions must agree so cross-company identifiers never authorize access. Signup identities without assigned membership cannot access company records.
- Clear client query caches when the authenticated identity changes so a prior company's fetched data cannot appear in another workspace.
- Operational photos/audio and applicant files use private storage and short-lived signed reads, resolving legacy public references to preserved object paths; branding and explicitly public training resources remain public by design.
- Employee loans are separate from fixed deductions: bounded period repayments and balance updates occur only inside the atomic payroll approval RPC and must be withheld from net pay; this is not creditor remittance or accounting posting.
- Prototype employees and flat test taxes remain in separate demonstration data, never authentication profiles or production statutory configuration.
- Workspace module defaults and route eligibility live in workspace-access; server-stored per-user module overrides may narrow role access, never elevate employees. Navigation, dashboard cards and direct page guards share the same access check; restrictive database policies and authenticated RPC guards enforce module access independently. Refresh roles from live protected tables, not stale JWT claims. Administrator roles retain full access.
- Account-free employees use employee_records with a durable employment key, never fabricated auth users; payroll reads both directories atomically and saves account-free payslips separately to preserve auth-bound foreign keys.
- Employee HR files use private storage and employee_documents metadata; HR manages files, staff read only explicitly shared own files, and downloads use short-lived signed URLs to keep confidential records private.
- Department payroll approval is an atomic authenticated RPC over live profiles; retain employee-name and department snapshots on payslips, reject duplicate employee/month approval, and consolidate saved runs by period without current-profile joins.
- Simulation clocks and punches use dedicated tables and authenticated RPCs; never override device time or feed simulated records into live attendance, payroll, billing or compliance. Resets start a new retained run rather than deleting history.
- Treat src/lib/sample-data.ts records as fictional demonstrations, never as authentication users; this prevents invalid payslip links and accidental live payroll.
- Serve the versioned user manual from public/training and author it with scripts/generate-user-manual.py so public downloads do not depend on database availability.
- The same manual generator also authors the versioned brochure; both Training Hubs use src/lib/training-resources.ts for current static PDFs so user-uploaded documents remain untouched.
- AI Payroll Officer is an on-demand, role-validated, read-only Edge Function using the Gateway SDK; send anonymized draft amounts/flags only, invalidate review on preview changes, and retain the atomic manager approval RPC as the sole payroll-save boundary.
- User creation and deletion authorization must be enforced server-side independently of operational access; hidden navigation is not a security boundary.
- Employee folders support reversible archiving and separately confirmed administrator-only permanent removal through a JWT-validated Edge Function and service-only tenant-checked RPCs; migrate auth-linked payslips to a non-restorable minimal financial identity before deleting login accounts, and retain resumable cleanup jobs so storage/auth failures cannot erase financial history.
- Employee sample edits remain session-only and explicitly separate from live profiles so fictional identities never enter payroll or account APIs.
- Platform selects retain native form semantics and string values with global styling and the shared native-select wrapper for HR/payroll controls; Input exposes native date/time pickers, while open-ended HR fields use ValuePicker with source-isolated directory suggestions to preserve custom details and sample/live boundaries.- Payroll runs carry pay type and start/end dates; salary and statutory thresholds are prorated by a period factor computed identically in src/lib/pay-period.ts and the payroll_period_factor SQL function, and approval rejects overlapping paid periods per employee to prevent double pay.
